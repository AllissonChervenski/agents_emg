# Requirements Quality Checklist: 002-dsp-streaming-pipeline

**Purpose**: Requirements quality validation for the DSP Streaming Pipeline feature (host-only, causal streaming sEMG pre-processing with stateful windowing and independent numerical oracles).  
**Created**: 2026-09-30  
**Feature**: [spec.md](../spec.md)  

**Review Ownership**: Reviewer-owned requirements-quality review artifact. Mark an item `[x]` only when the reviewer confirms the criterion is satisfied in the specification.  
**Marker Semantics**: `[x]` means the criterion has been verified for requirements quality. It does NOT mean code implementation is complete.  

---

## 1. Causality & Streaming Semantics

- [ ] CHK001 Is strict algorithmic causality ($y[n]$ depending only on $x[k]$ and $y[k]$ for $k \le n$) explicitly required without ambiguity? [Causality, Spec §FR-003, §FR-004]
- [ ] CHK002 Are non-causal operations such as `scipy.signal.filtfilt`, lookahead buffers, and whole-recording normalizations explicitly forbidden in runtime code? [Causality, Spec §FR-004]
- [ ] CHK003 Is chunk invariance ($process(\text{signal}) \approx \sum process(\text{chunk}_i)$) quantified with mathematical equivalence across arbitrary chunk sizes (1 sample to $N$ samples)? [Streaming, Spec §US2, §FR-003, §FR-010]
- [ ] CHK004 Is the behavior for variable and 1-sample chunk sizes explicitly defined and testable? [Streaming, Spec §Edge Cases, §FR-003]

## 2. Numerical Precision & Dtype Invariants

- [ ] CHK005 Is the numeric precision uniformly and unambiguously specified as `numpy.float32` across inputs, filter state vectors, and emitted windows? [Dtype, Spec §FR-008, Clarifications §2]
- [ ] CHK006 Is the prohibition against silent runtime promotion from `float32` to `float64` explicitly documented? [Dtype, Spec §FR-008]
- [ ] CHK007 Are NaN and Inf inputs identified with explicit validation rules and error behaviors? [Dtype, Spec §Edge Cases]

---

## 3. Scientific & Numerical Oracle Integrity (Constitution Principle VI)

- [ ] CHK008 Does the specification enforce that test oracles and golden vectors are computed independently (SciPy/analytical formulas) and NEVER generated by the code under test? [Oracle Integrity, Spec §FR-009, Constitution §VI]
- [ ] CHK009 Are test fixtures and reference datasets declared with SHA-256 immutability protection in `fixture_files` to prevent test tampering? [Oracle Integrity, Spec §FR-009, Constitution §VI]
- [ ] CHK010 Is there an explicit catalog of tolerance IDs (`tolerance_id`) defining `rtol`, `atol`, and mathematical rationales rather than arbitrary hardcoded global tolerances? [Tolerance Policy, Spec §FR-010]
- [ ] CHK011 Does the specification mandate multi-family provider separation (`test_designer` ≠ `test_validator` and `test_validator` ≠ `coder`) for numerical tasks? [Family Separation, Spec §FR-012]

---

## 4. Stateful Windowing Semantics

- [ ] CHK012 Are window buffer dimensions, strides, and memory layouts unambiguously defined with temporal index on axis 0 `(window_length, num_channels)`? [Window Semantics, Spec §US3, §FR-006, Clarifications §1]
- [ ] CHK013 Is the partial/residual window policy at end-of-stream explicitly specified (`drop` vs `pad`) with a safe streaming default? [Window Semantics, Spec §FR-007]
- [ ] CHK014 Is the return contract of `process_chunk` clearly defined for chunks that produce 0, 1, or multiple sliding windows? [Window Semantics, Spec §Clarifications §5]
- [ ] CHK015 Does the window buffer specification guarantee preservation of channel ordering and multi-channel synchronization? [Window Semantics, Spec §US3, §FR-006]

---

## 5. State Continuity & Reset Lifecycle

- [ ] CHK016 Are explicit state representation structures defined for both SOS biquad filters and sliding window buffers? [State Continuity, Spec §FR-003, §FR-006, Clarifications §4]
- [ ] CHK017 Is an explicit, deterministic `reset()` method specified for every stateful component to restore state vectors to zero? [State Continuity, Spec §Edge Cases]
- [ ] CHK018 Does the spec require phase and value continuity tests across chunk boundaries for multi-chunk synthetic signals? [State Continuity, Spec §US1, §US2]

---

## 6. Portability to C++ / Embedded Targets

- [ ] CHK019 Are runtime data structures and algorithms structured to prevent dynamic allocations or recursive constructs that would hinder C++/ESP32 porting? [Portability, Spec §NFR-004]
- [ ] CHK020 Are SOS filter coefficients required to be pre-computed static/versioned data arrays rather than designed dynamically during streaming? [Portability, Spec §FR-005]
- [ ] CHK021 Is memory organization aligned to contiguous 1D/2D arrays suitable for embedded C-contiguous buffers? [Portability, Spec §NFR-004, Clarifications §1]

---

## 7. Containment of Dataset & Hardware Assumptions

- [ ] CHK022 Are all physical parameters (sampling rate, electrode channels, cutoffs, window times) explicitly tagged as `FIXTURE_ONLY`, `PROVISIONAL`, or `DECISION_REQUIRED`? [Dataset Assumptions, Spec §DECISION_REQUIRED]
- [ ] CHK023 Does the specification strictly avoid embedding hidden assumptions from specific public datasets (NinaPro, CapgMyo)? [Dataset Assumptions, Spec §NFR-002]
- [ ] CHK024 Is the scope strictly confined to host-only Python without premature ESP32, FreeRTOS, ADC, or DMA code dependencies? [Scope Invariant, Spec §NFR-001]
- [ ] CHK025 Is property-based testing (Hypothesis) documented as `DECISION_REQUIRED` prior to introducing new library dependencies? [Scope Invariant, Spec §DECISION_REQUIRED-05, NFR-003]
